# 一括データから知識表の項目を書く班への指示

目的は TEAM_BRIEF.md と同じ（日本の中小製造業が、AI検索に引用され、見込み客に選ばれるブログ記事を書くための「製造業の知識表」を増やす）。今回は検索ではなく、国の公開データ（補助金の採択一覧・成果事例）の行を読み、要点を自分のやさしい日本語でまとめる。

## 守ること（いちばん大事）
- 会社名・人名・法人番号・市区町村名は一切書かない。1社だけの話を書くときは都道府県も書かない（「金属加工の会社」「従業員の少ない町工場」のように）。
- 事業計画名・概要の文章をそのまま写さない。短く言い換える。
- 数字・事実を作らない。データにある内容だけ。件数を書くときは、自分が渡された行を数えた数だと分かるように（「一覧の一部を数えると」など）か、件数を書かない。
- 計画（これからやること）を「成果が出た」と書かない。事業再構築の行は「採択された計画」、ものづくり補助金の成果事例検索の行は「成果事例として紹介された取り組み」。

## 書くもの（1班 120〜150件）
- success：同じ業種の会社が取った「強みの生かし方・新しい市場への出方・設備の生かし方」の型。2件以上の行に共通する型を中心に、具体的で面白い1件の話も混ぜる。summary に「元の強み → 新しくやること → ねらう相手」が分かるように。
- pain：既存事業がなぜ苦しくなったか（受注減、海外移転、人手不足、原材料高、取引先の内製化など）。概要の前半に書かれていることが多い。業種ごとに具体的に。
- buyer / question：その転換で新しく相手になる発注者が、何を知りたがりそうか（新しい市場の買い手の疑問）。行から無理なく言えるものだけ、少なめでよい。
- articleIdea（40字以内）：その型を使ってブログ記事を書くなら、の題名案。success と pain にはなるべく付ける。
- useFor：success は ["article_idea","question_example","writer_hint"]、pain は ["question_example","shiori_tip"] を基本に。
- industries：TEAM_BRIEF.md にある業種名から選ぶ（当てはまらなければ "all"）。
- title は30字以内で、項目ごとに言い回しを変え、具体的に（同じ書き出しを何十件も続けない。よく似た見出しは後で重なりとして捨てられる）。summary は120字以内。

## 出典（source）
渡されたファイルの行にある url を使う。
- 事業再構築補助金の行：{"title": "事業再構築補助金 第N回公募 採択案件一覧（事業計画の概要・製造業）", "url": 行の url, "publisher": "事業再構築補助金事務局（中小企業庁）", "date": "2026-10"}（N は行の round）
- ものづくり補助金の行：{"title": "ものづくり補助金 成果事例検索", "url": "https://portal.monodukuri-hojo.jp/jireisearch.aspx", "publisher": "全国中小企業団体中央会", "date": 行の年度を西暦にした "YYYY"}（型が複数年にまたがるときは、いちばん新しい年）

## 出力
JSON 配列を、指示されたファイル名で作業フォルダ（このファイルと同じフォルダ）に python で書く。形は TEAM_BRIEF.md の通り。書いたら python で、JSON が読めること・長さ・会社名らしき語（株式会社・有限会社・(株) 等）が無いこと・existing_titles.txt と見出しが重ならないことを確かめ、5行で報告（何件・どんな型が多かったか・弱いところ）。WebSearch は使わない。
