# AIO：このサービスが目指すこと

最終更新：2026-10-25（次の見直し：毎週月曜の定期更新。下の「更新の決まり」）

AIO（AI検索に紹介されるための工夫）は、このサービスを作るときの土台の考え方です。画面、質問、AIへの指示、点検は、すべてここに合わせます。AI検索の仕組みは日々変わるため、このファイルは常に最新に保ちます（田村さん、2026-10-23）。

## このサービスの定義（2026-11-03 田村さん）

**AIに選ばれて、これから出会うお客様に選ばれる会社へ。そこまで、AI（案内役のしおり）が伴走する。**

田村さんの言葉：「AIがAIOに選んでもらうために伴走する。何よりも大切なのは、AIに選んでもらった後に人に選んでもらうこと。これを基本に組み込みたい。このサービス全体の定義」

| 段階 | 何が起きるか | このサービスがすること |
|---|---|---|
| 1. AIに選ばれる | お客様がAIに相談したとき、答えの中で「この会社がいいよ」と紹介される（AIO） | AIが紹介しやすい材料（体験・数字・誰が/どこで・質問と答え・プロの知見）を、一問一答で聞いて記事にする |
| 2. お客様に選ばれる（いちばん大切） | 紹介されて読みに来た人が「ここに頼みたい」と思い、問い合わせる | 読んだ人が安心して頼める材料（比べたときの違い・次の一歩・正直な言葉・正しい数字・この会社の人の言葉）を残す |

- AIに紹介されても、読んだ人に選ばれなければ売上にならない。だから2がいちばん大切。AIのための工夫で、人が読みにくくなったり、会社の人柄や言葉が消えたりしてはいけない
- 言葉と見た目と、AIへの指示は src/lib/brand.ts から同じものを使う（SERVICE_PROMISE、CHOSEN_STAGES、PURPOSE_FOR_AI）。9つの材料は、それぞれ「AIに選ばれるため（why）」と「お客様に選ばれるため（people）」の両方の理由を持つ（src/lib/aio.ts）。AIOのチェックの13項目は、おもに効く段階で2つに分けて見せる（src/lib/aioCheck.ts の stage）
- 「伴走」は、しおりが最初の質問から、記事・チェック・ブログに載せたあとまで、となりで案内し続けること。決めるのは会社の人で、AIが勝手に事実を作らない
- **書く記事は、人の心を動かし、かつAIOがなされていること**（2026-11-03 田村さん「実際に生成する文書（ブログ）も人の心を動かすこと、AIOがなされていること。それを意識して」）。書き出しはお客様の困りごとの場面から、お客様の言葉はそのまま、作り手が大切にしたことを会社の人の言葉で残し、最後は読者へのひとことと次の一歩。同時に、見出しは問い・各節の最初に短く答える・数字と地域をはっきり書く。気持ちやお客様の声を作らない（src/lib/ai/prompt.ts）
- 質問（ヒアリング・記事の質問・深掘り・AIOのチェックの聞き返し）も、AIに選ばれる材料だけでなく、お客様の気持ちと作り手の想いを聞く。記事の質問に「お客様が喜んでくれた言葉や、この仕事で大切にしたこと」（q6）を足した
- 紹介するかどうかはAIが、頼むかどうかは読んだ人が決める。画面では「選ばれる」「売上が上がる」を約束しない。「選ばれやすい材料をいっしょにそろえる」と言う

## 選ばれる決め手（2026-11-07 田村さんの参考資料から）

出典：田村さんが共有した、株式会社ルーシー（バズ部）の資料「集客施策をやってるのに なぜ売上が伸びないのか」（2026年）と、同社の事例ページ「司法書士法人ミラシア」（https://lucy.ne.jp/bazubu/case/mirasia）。どちらも対策会社の自社の発表で、数字は自社の計測。「対策会社の宣伝記事だけを根拠にしない」の決まりどおり、考え方の参考にし、数字は顧客の画面に約束として出さない。

**要点**
- 売上＝アクセス数 × 問い合わせ率（CVR）× 成約率 × 客単価。多くの会社は集客（アクセス）ばかり増やし、「選ばれる」側（CVR）を後回しにしている
- AIで調べる人は、自分の状況を詳しく話して「私の場合どこがいい？」と聞き、AIは理由つきで1〜3社を紹介する。紹介されてサイトに来る人は「意思決定の8割が終わった」状態で、最後の確認に来る。だから来たあとの中身（強みと事例）で決まる。中身で「やっぱりやめよう」と思わせると大きな損になる
- AIは「この会社を紹介する理由」を組み立てられない会社を外す。「何でもやります」より「〇〇に特化、根拠はこれ」。抽象的・自画自賛・根拠なしの言葉（「丁寧な対応」「豊富な実績」）は、AIにも人にも無視される。AIに選ばれることと人に選ばれることは、本質的に同じ
- AIは1社の自己申告だけでは信用しない。業界の媒体・取材・第三者の言及など、ほかの場所でも同じことが言われていると信頼する
- 4つを、この順番で：①注力するお客様を1つの姿に絞る ②そのお客様への強みを、根拠と数字で言葉にする ③事例で強みを証明する ④どのページでも「〇〇の専門家」と伝わるよう一貫させる（ブログ記事もそのお客様のテーマが中心）。よくある失敗は「お客様も強みも決めないまま記事を書き始める」
- よい事例の6つの要素：①お客様の状況（業種・規模・困りごと）②頼む前の状態（できれば数字）③やったことと順番 ④頼んだ後の変化（数字と期間）⑤お客様自身の言葉 ⑥この会社の強みがどう効いたか。「A様・50代・大満足」の短文の羅列は効かない。狙うお客様に合う事例が3本以上あるかが目安
- ミラシアの事例：最初の3か月は強みの言語化だけ（客像を決め、「その人ならAIでどう調べるか」を整理）→ 強みを長い文にして公開 → 事例を1本ずつ「なぜうちが選ばれたか」の核を掘って量産（3〜4か月で約50本）。いちばん時間がかかるのは文章化ではなく、その核を見つけること。成果の要因として代表が挙げたのは「強みの徹底的な言語化」と「続けられる仕組み」。狙いは「AIに紹介されること」ではなく「強みとセットで紹介されること」

**このサービスでやること（2026-11-07 反映）**
- 書き手（src/lib/ai/prompt.ts の SYSTEM_PROMPT）：誰に向けた記事かをはっきりさせる／強みはどの会社にも書ける言葉で終わらせず、素材にある根拠と数字で書く（無ければ作らず needs_info で聞く）／事例は6つの要素の流れで書く（素材に無い要素は作らない）／会社の専門と結び付ける
- 点検役（REVIEW_SYSTEM_PROMPT の aio）：上の4つが書けているかを見る
- AIOのチェックに「強みの根拠」（proof、お客様に選ばれる）を足して13項目に。誰に向けた強みか・根拠・数字があるか、どの会社にも書ける言葉だけになっていないかを見て、足りなければ聞き返す（src/lib/aioCheck.ts）
- ヒアリングの深掘り（FOLLOWUP_SYSTEM_PROMPT）：強みの答えが「丁寧」「親身」だけなら、何をしているか・根拠・数字を聞く。お客様の答えは、いちばん力になれるお客様の姿に絞れるよう聞く。ヒアリングの質問の数は変えず、ヒントの文だけ直した
- キーワードの提案（PROPOSAL_SYSTEM_PROMPT）：①誰に ②強み ③事例 ④一貫、の順番を守る。3案とも1つの見込み客の姿に向け、why の最初に誰向けかを書く。会社の専門から離れたテーマに広げない。各案に「依頼の直前に確かめたいこと（費用・違い・流れ）」の記事と「お客様の事例」の記事を1本以上入れる
- 書く記事リスト（キーワード管理表）：「頼むかを決める『お客様の事例』 x / 3本」を出し、足りなければ事例の記事を足すよう声をかける（src/prototype/keywords.ts の caseStudyHint）
- まだやっていないこと（次の候補）：会社ごとの「強みの文」（長い文）を土台として持ち、すべての記事に読み込ませる／事例の記事専用の一問一答（6つの要素と「なぜうちが選ばれたか」を聞く）／効果を「AIの答えに、強みと一緒に名前が出るか」で確かめる方法／ほかの場所（取材・業界の媒体）でも同じ強みが語られるようにする助言

## なぜAIOが必要か

**AI時代に、ウェブサイトで売上を上げるため。**（田村さん、2026-10-23）

- お客様は Google で検索するだけでなく、AI（Google の AI による概要、ChatGPT など）にも相談するようになった
- AIは答えの中で、会社や記事を紹介する。紹介された会社に問い合わせが来る
- だから、AIに「この地域でこのことなら、この会社」と紹介される記事を、顧客が自分で書き続けられるようにする

## いま分かっている公式の考え方（2026-10-25 時点）

公式のページは、この作業環境からは直接開けなかった。下は検索結果と報道からの要約で、正確な文言は未確認。

**Google（AIによる概要・AIモード）**
- 公式の説明ページは「AI features and your website」（https://developers.google.com/search/docs/appearance/ai-features）。AIによる概要は関連サイトへのリンクを出し、1つの質問を関連する複数の検索に広げて（クエリ・ファンアウト）答えを作る。通常の検索より役に立つときだけ出る。SEOの基本はAIの機能にもそのまま当てはまる
- 2026年5月15日に、生成AIの機能に向けた最適化の案内が出た（その後も更新）。要点は「AIへの最適化も検索への最適化であり、SEOのまま」。検索に出られる状態（クロールでき、スニペットを出せる）と、独自の内容、画像と動画の質が大事
- やらなくてよいと明言されたこと：llms.txt（Google検索は使わない）、記事を細かく区切ること（理想の長さは無い）、AI専用の構造化データ、不自然な言及集め（スパムとして除かれる）
- 2026年6月の報道：AIの機能に自分のサイトを使わせるかを選べる設定を、Search Console で試している。使わせない場合、AIの機能からの表示と流入は無くなる。英国の競争当局（CMA）の命令を受けて英国から先に始まり（2026年6月）、2026年8月31日に世界中に広がったと報道されている（公式の確認は未確認）。対象は AIによる概要・AIモード・Discover のAIによる概要で、Gemini アプリは対象外（報道）
- 2026年6月3日の公式ブログ：Search Console に「生成AIの掲載結果」のレポートができた。AIによる概要・AIモードでの表示回数、ページ、国、日付が見られる（2026年5月18日以降のデータ）。クリック数と検索語は無い。はじめは一部のサイトだけだったが、2026年8月31日にすべてのサイトに広がったと公式ブログに追記された（報道で確認）。データが少ないサイトには出ないことがある。Search Console の API ではまだ取り出せない（報道）
- 2026年10月15日の公式の発表（Google の Keyword ブログ「More ways to connect with the web from Search」）：AIモードとAIによる概要で、文中のリンクをより上に、より多く出す。答えの終わりのリンクに画像を付ける。手続きなどで「公式の場所」になる1〜2サイトを答えの上に出す枠を試験中。ニュースの記事の並び（カルーセル）を国と言語を広げて出す。「優先するソース」の利用は年初から7倍超。流入が増えたかの数字は出していない（公式ページは未読、報道で確認）

**OpenAI（ChatGPT の検索）**
- ChatGPT の検索に出るには、サイトが OAI-SearchBot（検索用のクローラー）を拒否していないこと。学習用の GPTBot とは別に設定できる。出る位置は保証されない。順位の付け方は公開されていない
- 2026年10月時点で、引用の仕方を変えたという公式の発表は見つからなかった。調査会社の集計（Ahrefs など、2026年3月と9月の比較）では、Reddit や Wikipedia の引用が減り、一次調査・公的機関・実際に試した記事の引用が増えたとされる。調査会社の数字で、公式の確認は無い（報道・未確認）

**Perplexity・Claude**
- 2026年10月に、引用の条件が変わったという公式の発表は見つからなかった（未確認）

**このサービスへの意味**
- 小手先の技（専用ファイル、専用の目印、細切れの記事）より、その会社にしかない体験・数字・答えを、読む人に役立つ形で書くことが一番の近道。下の「材料」はこの考え方に沿っている
- Google も ChatGPT も、引用先をはっきり見せる方向に動いている（Google は2026年10月にリンクを上に出すと発表）。「この会社にしかない体験」と「問い合わせできる次の一歩」が、紹介されたあとにクリックと売上につながる
- 顧客のサイトの設定（robots.txt で Googlebot や OAI-SearchBot を拒否していないか、ページがクロールできるか）は、コタムが最初に確かめる項目にする（チェック項目の画面は未作成）

## AIに紹介される記事の材料

その会社の記事が紹介され、読んだお客様に選ばれるための材料を9つにまとめた（2026-11-03 に「気持ちと想い」を足した）。画面では、質問ごとに「どの材料のために聞いているか」を伝える（src/lib/aio.ts の AIO_POINTS）。

| 材料 | 中身 | 聞いている質問 |
|---|---|---|
| 体験（一次情報） | その会社にしかない実際の相談、対応、結果。一般論はAIに紹介されにくい | ヒアリング「選ばれる理由」、記事「どんな相談があったか」 |
| 具体的な数字 | 価格、期間、件数、年数。AIが答えに引用しやすい | 記事「結果はどうだったか」、深掘りの質問 |
| 誰が・どこで | 会社名、地域、資格、事業の中身。AIが「この地域ならこの会社」と結び付けやすい | ヒアリング「お仕事」「地域」 |
| 質問と答え | お客様がAIに聞く質問は、ふだん会社が聞かれている質問と同じ。そのまま答える | ヒアリング「お客様」「よく聞かれる質問」、記事「どう答えたか」 |
| 比べる材料 | 選び方、違い、頼み先ごとの特徴。迷っている人の質問に使われる | ヒアリング「比べられる会社」 |
| プロの知見 | 注意点、よくある誤解。専門家だから書ける信頼の材料 | 記事「よくある誤解」 |
| 気持ちと想い | お客様の困りごとの気持ち、喜んでくれた言葉、作り手が大切にしたこと。読んだ人の心が動き「この人に頼みたい」につながる。経験にもとづく一次情報でもある | 記事「お客様が喜んでくれた言葉や、この仕事で大切にしたこと」、ヒアリングの深掘り |
| 次の一歩 | 読んだ人がすぐ問い合わせできる出口。売上につながる | ヒアリング「売りたいサービス」、記事「次に何をしてほしいか」 |
| 信頼 | 大げさな言葉や根拠のない言い切りをしない。正確さが紹介される近道 | ヒアリング「使ってほしくない言葉」 |

記事の組み立て（柱の記事と周りの記事＝ピラーとクラスター）も、「この会社はこのテーマにくわしい」と伝えるためのAIOの工夫の1つ。これだけにこだわらない。

## 作るときの約束

- 質問を増やすときは、どの材料のためかを決めてから足す。理由を言えない質問は足さない
- 顧客には「AIOのためにくわしく聞いている。AI時代に売上を上げるため」を、明るく、励ましながら伝える。答えるたびに、集まった材料を見せる
- 材料が無いのに、数字や実績をAIに作らせない（作り話はAIOにも信頼にも逆効果）
- 点検役（Claude）は、この9つの材料が記事に入っているかを見る。足りなければ、顧客に追加で聞く質問を返す（T5-4）
- 効果は、第2段階から Search Console の表示回数と検索語で確かめる。Google のAIの機能での表示回数は、Search Console の「生成AIの掲載結果」で見られるようになった（2026年8月31日から全サイト。クリック数と検索語は無く、API でも取り出せない）。ChatGPT などでの紹介回数を直接測る方法は未確認

## 更新の決まり

- 毎週月曜に、AI検索（Google、ChatGPT、Perplexity、Claude など）の公式の発表と信頼できる報道を確かめ、変わったことをこのファイルに書き足して PR を作る（定期の作業として設定済み）
- 海外（英語）の公式発表・報道に加えて、国内のAIOの実績や事例（信頼できる報道・調査）も読む。事例から分かった書き方は、出典つきで知識表に足す（2026-11-02 田村さん。待ち画面のコラム「コタムのこだわり」で、お客様にもそう伝えている）
- 書き足すときは、日付・出典・「公式か報道か」を必ず書く。確かめられないことは「未確認」と書く
- 同じPRで、AIOの知識表（src/lib/aioNews.ts の AIO_NEWS）にも1件ずつ足し、AIO_NEWS_UPDATED をこのファイルの「最終更新」と同じ日にする（そろっていないとテストが落ちる）。知識表は、顧客の画面の「しおりのAIOニュース」と、質問の「なぜ聞くの？」の最新情報、書き手（GPT）と点検役（Claude）への指示に使われる
  - title と forClient は、顧客（中小企業の社長や担当者）に向けたやさしい言葉で書く。関係する材料があれば point と soWeAsk（「だから〇〇を聞いています」）を書く
  - forWriter・forReviewer（AIへの指示）は、公式の発表で、正式に始まったものだけに書く。試験中の機能と、報道・調査だけのものには書かない（テストで確かめる）。素材にない事実を作らせる指示は書かない
  - 古くなって当てはまらなくなった項目は消す。表は新しい順
  - 毎週の定期作業もこの手順に従う（知識表を直すのはコードの変更だが、この作業の一部として行ってよい）。PRを作る前に `npm run lint`・`npm run typecheck`・`npm test` を通す
- 材料や質問の考え方が変わる場合は、docs/DECISIONS.md に理由を書き、src/lib/aio.ts の AIO_POINTS と質問も合わせて直す
- 対策会社の宣伝記事だけを根拠にしない
