# 読みもの（/column）のテーマ候補と、毎日1本の進め方

2026-11-08 田村さん「AIOの読みものをどんどん拡充したい。写真もAI生成と思われないレベルで、しおりがチャットで答えている感じで目を飽きさせない。一日1本記事を上げていきたい」。同日「写実的なものとしおりがあると違和感。しおりに聞いてみた、みたいに控えめに」で、しおりのイラストをやめ、図と写真の形に変えた（手本 llmo）。

## 毎日1本の進め方（定期作業もこの通りに動く）

1. 下の「候補」の一番上の `- [ ]` を1つ選ぶ（書きにくければ次へ。理由をこのファイルに1行残す）
2. `src/lib/column.ts` の COLUMNS の**先頭**に1本足す。**手本は `llmo`**（2026-11-08 田村さん「写実的な写真としおりが混ざるとAIっぽい。しおりは控えめに」→ 3AI・9人の採点で9.5点に届いた形）
   - 並び：答え（summary）2〜3行 → 前置き（intro）1〜2文。急ぐ人向けに見出しへの案内（jump）を付けてよい → 見出しは問い・最初に短い答え → 図か写真 → 本文 → 結び（closing）1文
   - **しおりのイラストは使わない**（写真と混ぜるとAIっぽい）。`opening`・`shiori`（しおりの問いかけ・ひとこと）も書かない。`scripts/column/shiori.mjs` は読みものには使わない
   - 写真は冒頭（hero）に1枚。人の顔・ロゴ・文字・電話機やメモなどの「場面の小道具」を盛らない、ありふれた1枚（例：作業台に図面とノギスだけ）。`node scripts/column/photo.mjs <slug>-<名前> "<場面（英語）>"`。開いて四隅まで見て、ロゴ・文字・透かしがあれば作り直す
   - 見出しごとに写真か図を1つ（column.test.ts が見張る）。図は `figure` に書く：`flow`（流れ）・`table`（2列の表）・`pair`（2つを並べて比べる。すすめる側があるときだけ `strong` を付ける）・`check`（確かめること。項目ごとに note で中身を書く）。図の注記（note）は「とは限りません」など1つだけにし、同じ断り書きを本文と重ねない
   - 「しおりに聞いてみた」（chat）は**見出しが4つなら2か所、5〜6つなら3か所**。1つの見出しに1問だけ、隣り合う見出しに置かない（図のある見出しのあと、本文の区切りに置く）。読む人（製造業の社長）の素朴な質問・迷いに、最初の一文で答え、2文目で「誰に何と聞くか／何をするか」を1つだけ書く。念押しを足さない（2026-11-09 田村さん「読むのは製造業の社長。対話は一度だけじゃない方が見やすい」、column.test.ts が数と位置を検査）
   - 前置き（intro）は、しおりが吹き出しで話す（ColumnIntro）。introMood に記事の話に合う表情を選ぶ（ask・bow・cheer・coffee・idea・joy・point・right・surprise・think・welldone）。一つ前の記事（COLUMNS で隣）と同じ顔にしない。しおりの口から出る言葉なので、です・ます体で、地の文の硬さを残さない（2026-11-09 田村さん「シンプルになりすぎた。出だしをしおりにしゃべらせて。いろんな表情も」、column.test.ts が検査）
   - しおりは途中でも1回（chat のない、最初でも最後でもない見出しの終わりに talk）、結び（closing）でも吹き出しで話す。talk は35〜60字の、その見出しを受けた実感やコツのひとこと（次の見出しの予告や「メモしてください」の作業指示を並べない）。closingMood を付け、出だし・途中・結びは違う顔にする（2026-11-09 田村さん「途中でもういっかい出てくるくらい。最後の結びもしゃべらせて」）
   - 画面では、質問→答えの前に「…」を0.5秒だけ見せてから答えを出す（ColumnChat。動きを減らす設定と印刷では最初から全部出す）
   - 関連する読みものへは `see`（記事名のリンク）を使う
   - 画面の順は「答え→図/写真→body→after→see→聞き書き→しおりに聞いてみた」。聞き書きを受ける文（「この聞き書きを掲載文にすると」）は after に置かず、body で「下の聞き書きの例なら」と先に書く（2026-11-09 校閲で指摘。equipment は未修正）
   - alt は40字以上で、何が・どこで写っているか、記事のどの話を表すかまで書く
   - 言い回し：「順に見ていきます」「〜してみてください」の連発、かっこ書きの断り、決めぜりふは避ける。当サイトの提案と公式の案内（Google など）は分けて書き、保証しないことは1回だけ書く
   - 毎日の自動記事は、先頭への1本追加だけにする。既存の記事・写真には触らない（直すときは別の作業で）
3. 書いてはいけないこと（docs/LESSONS.md・/about の編集方針）：他社の料金や比較、「〇〇すれば紹介される」の言い切り、確かめていない画面や手順、Googleの見解をほかのAIに広げること、架空を実績に見せること、既存のお客様の扱い（招待・無料）、料金ページとの食い違い
4. 3AIで点検：`/tmp` などに記事を書き出し、GPT・Gemini に「事実の誤り・言い過ぎ・分かりにくさ・10点満点の採点」を聞く。9.5点に届くまで直す（Claude は自分で点検役をする）
5. `npm run typecheck && npm run lint && npm test && npm run build` を通し、375px・1280px で横スクロールが出ないことを見る
6. 候補の `- [ ]` を `- [x]`（日付・slug）にして、PRを作り、マージする（田村さんの方針：毎回聞かずにマージ）
