# 読みもの（/column）のテーマ候補と、毎日1本の進め方

2026-11-08 田村さん「AIOの読みものをどんどん拡充したい。写真もAI生成と思われないレベルで、しおりがチャットで答えている感じで目を飽きさせない。一日1本記事を上げていきたい」。

## 毎日1本の進め方（定期作業もこの通りに動く）

1. 下の「候補」の一番上の `- [ ]` を1つ選ぶ（書きにくければ次へ。理由をこのファイルに1行残す）
2. `src/lib/column.ts` の COLUMNS の**先頭**に1本足す。型は既存の記事と同じ
   - 答え3行 → しおりの問い → 見出しは問い・最初に短い答え → 「架空の例」と明記した聞き書き（任意）→ しおりのひとこと
   - 写真：題名の下に1枚（hero）＋節に1枚（photo）。`node scripts/column/photo.mjs <slug>-1 "<場面（英語）>"`。文字・ロゴ・顔のアップが入ったら作り直す。1枚おおむね数円〜十数円
   - しおりのイラスト：`node scripts/column/shiori.mjs <slug>-<番号> "<しおりがしている場面（英語）>"`。手本のしおりの絵を渡し、Geminiに「ウォーターマーク・署名・文字・ロゴ・本物の画面なし」と頼む（2026-11-08 田村さん「この方向でOK」「ウォーターマークなしで、とお願いして」）。それでも四隅を拡大して確かめ、入っていたら作り直す。記事では `illustration: true` を付ける（イラストには注意書きを出さない。田村さん「AIにやらせてるっぽさが出る」）
   - ウォーターマーク（隅のマークや透かし文字）が入った画像は使わない。四隅まで見て、入っていたら作り直す（2026-11-08 田村さん「ウォーターマーク外してね」）
   - alt は40字以上で、何が・どこで・何をしている場面か、記事のどの話を表すかまで書き、写真は最後に「（イメージ写真）」と添える（2026-11-08 田村さん「altタグなどにもしっかり情報いれること」）。しおりのイラストは alt を60字以上にし、「イメージ」の断り書きは画面に出さない（column.test.ts が見張る）
   - 「しおりに聞いてみた」（chat）を1〜2か所。読んでいる社長の素朴な質問に、しおりが短く答える。一般的な説明だけで、架空の実績や数字は入れない
3. 書いてはいけないこと（docs/LESSONS.md・/about の編集方針）：他社の料金や比較、「〇〇すれば紹介される」の言い切り、確かめていない画面や手順、Googleの見解をほかのAIに広げること、架空を実績に見せること、既存のお客様の扱い（招待・無料）、料金ページとの食い違い
4. 3AIで点検：`/tmp` などに記事を書き出し、GPT・Gemini に「事実の誤り・言い過ぎ・分かりにくさ・10点満点の採点」を聞く。9.5点に届くまで直す（Claude は自分で点検役をする）
5. `npm run typecheck && npm run lint && npm test && npm run build` を通し、375px・1280px で横スクロールが出ないことを見る
6. 候補の `- [ ]` を `- [x]`（日付・slug）にして、PRを作り、マージする（田村さんの方針：毎回聞かずにマージ）
