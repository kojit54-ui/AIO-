# 製造業の知識表を集め直す手順（週2回の定期作業）

2026-11-05 田村さん：「この調査を、新しい調査先を広げつつ週に2回実施。新たな製造業事例を増やすことに注力。それをしおりの質問や文書作成、キーワード提案に活かす」。

知識表そのものの説明は docs/MANUFACTURING.md。ここは「どう集めて、どう足すか」の手順と、これまでに使った調べ先の記録。

## 1回の流れ

1. `main` から作業ブランチを切る（例：`claude/mfg-research-YYYYMMDD`）。
2. 作業フォルダ（リポジトリの外。例：`/tmp/mfg-research`）に、今ある見出しと出典URLを書き出す。
   `python3 scripts/manufacturing/merge.py --export /tmp/mfg-research`
   → `existing_titles.txt`（種類<TAB>見出し）と `existing_urls.txt` ができる。
3. 下の「調べ先の記録」を読み、**まだ使っていない角度を6つ**選ぶ。国内の製造業の事例（success：Web・発信・販路で成果が出たやり方）を中心にする。
4. 6つの班（サブエージェント）に分けて調べる。各班に、このファイルの「班への指示」をそのまま渡し、担当の角度とファイル名（`/tmp/mfg-research/NN_角度.json`。海外は `ovNN_角度.json`）を伝える。
   - WebSearch は1ターン全体で200回が上限。**1班25回まで**と必ず書く（10班×40回にしたら全班が20回前後で止まった）。
5. 全班がそろったら、まず見るだけで件数を確かめる：`python3 scripts/manufacturing/merge.py /tmp/mfg-research`
   問題なければ `--write` で data.json に書き込む（`| head` でつなぐと最後の書き込みの前に止まる。最後に written と出たか確かめる）。
   班の報告で「出典の当てはめが推測」とされたもののうち、数字を含むものは外す。
6. `npm run lint`・`npm run typecheck`・`npm test` を通す。
7. docs/MANUFACTURING.md の「収集」の節に1行（何回目・何件・どの角度）、このファイルの「調べ先の記録」に使った角度を足す。docs/HANDOFF.md にも1行。
8. コミット → push → PR → マージ（田村さん「毎回聞かずにマージして」）。
9. 田村さんへの報告は短く：国内◯件／海外◯件になったこと、増えた中身を3つほど、管理画面のリンク https://aio-erabare.jp/admin/knowledge 。

## 班への指示（そのまま渡す）

目的：日本の中小製造業（一人親方〜30人規模の町工場など）が、AI検索に引用され、読んだ見込み客（発注する設計・購買担当、試作したい開発者、個人、求職者）に選ばれるブログ記事を書くための「製造業の知識表」を増やす。

- 道具：WebSearch（mode "standard"。薄いとき・新しい話は "extended"）。**検索は25回まで**。WebFetch は日本のサイトの多くで使えない（試すのは1回まで）。
- 重ねない：作業フォルダの existing_titles.txt・existing_urls.txt、同じフォルダの他の *.json と、見出しも出典URLも重ねない。
- 書き方：
  - 文章は写さない。要点を自分のやさしい日本語で（title 30字以内、summary 120字以内、articleIdea 40字以内）。
  - source.url は、検索結果に実際に出たURLだけ。URL・数字・法律・調査結果を作らない。数字は結果に書いてあるときだけ、誰がいつ発表したかと一緒に。制作会社・ツール会社の数字は「◯◯社の発表によると」と分かるように。
  - 中小の会社名や個人が分かる情報は書かない（「従業員15人ほどの金型会社」のように）。大手は、公開資料に名前が出ているときだけ。
  - 1つの発行元から5件まで。古すぎる情報（2015年より前）は、技術の基本の話以外は避ける。
- 海外の事例・調査は "region": "overseas" を付け、summary の頭に国・地域を書き、ファイル名を ov で始める。日本の会社が海外に出る話、海外の規格・規制の説明は国内の扱い。
- 出力：JSON 配列を、指示されたファイル名で Bash（python）で書く。60〜90件。各要素：
  `{"kind": "pain"|"question"|"success"|"buyer"|"trend"|"term", "title": "...", "summary": "...", "industries": ["all"] か業種名, "useFor": ["question_example","article_idea","writer_hint","shiori_tip"] から, "articleIdea": "（任意）", "official": true/false（trend のときだけ）, "region": "overseas"（海外のときだけ）, "source": {"title":"...","url":"https://...","publisher":"...","date":"YYYY-MM か YYYY か null"}}`
  - kind：pain＝作り手の悩み、question＝読む人の疑問とその答えに入れるとよいこと、success＝Web・発信・販路でうまくいったやり方、buyer＝買い手の探し方・決め方、trend＝最近の動き（国や団体の正式な発表は official:true）、term＝発注者がつまずく言葉のやさしい説明
  - industries に使える業種（「、」区切り。「刃物・工具」のように「・」を含むものは1つの名前なので、そのまま書く）：切削加工、研削、放電加工、板金、プレス、溶接、製缶、樹脂成形、ゴム、金型、鋳造、鍛造、熱処理、表面処理、塗装、食品製造、化粧品OEM、印刷、パッケージ、印刷機械、木工、繊維、電子部品、基板実装、組立、装置、治具、3Dプリンタ、金属加工、機械部品、ばね・線材、ねじ・締結部品、歯車、パイプ加工、医療機器、半導体、自動車部品、航空宇宙、看板・サイン、ガラス・セラミック、化学・塗料・接着剤、建材・金物、刃物・工具、食品機械、産業機械、精密機器、紙加工、プラスチック加工品、酒・醸造
- 書き終えたら python で JSON が読めること・長さの上限・重なりが無いことを確かめ、5行で報告する（何件・何を集めたか・弱いところ・出典の当てはめが推測のもの）。

## 困りごとを探す人の目線（ラッコキーワード、2026-11-09〜）

発注する人・困っている人が実際に検索する言葉から、上位ページとGoogleの「AIによる概要」に引用されているページを巡って、読む人の疑問と答えに入れるとよいことを集める。班への指示は scripts/manufacturing/rakko/RAKKO_BRIEF.md（ラッコキーワードMCPを使う。クレジットは班ごとに90まで、5班で約250）。

- question-search（よくある質問、1.5）：業種の言葉＋「依頼・費用・小ロット」など。消費者のノイズ（車の板金修理、ばね指、DIY）は notIncludes で外す
- headline（上位20ページの見出し、3）：多い疑問の答えに何を入れると上位に出るか
- influx-aio（AIに引用されているキーワードと回答、4.5。同じ条件のページ送りは1時間無料）：ドメインを指定して、発注者向けの言葉で絞る
- 外すもの：知恵袋など個人の回答が出典のもの、題名だけで書いた資料、AIの回答にある先の見通し（「いつまで続く」など）、当社のお客様のサイトが出典のもの
- AIの回答は Google の文章なので写さず、事実の要点だけを書き直す。出典は引用されたページ
- ラッコのクレジットはお客様の画面のキーワード提案にも使う。月3,000付与（月末に持ち越し分が切れる）なので、1回の収集は300までにする
