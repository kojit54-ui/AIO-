# UI：画面・文言・状態

## 共通ルール

- 専門用語を減らし、次の操作をひとつずつ示す。主導線のボタン文言は「今月の記事を書く」
- 本文16px以上、すべての入力欄にラベル、キーボードだけで操作可能、十分なコントラスト（WCAG AA相当）
- 色とロゴは仮置き
- 画面試作の段階では、生成結果は「サンプル（AIは未接続）」と画面上に明示する

## 見た目と動き（2026-11-01 田村さんが案Bを選択）

素人がとっつきやすく、システム感がなく、動きで書く人のやる気を保つ。見本：https://claude.ai/artifact/CmzY3oipuQnGUGQKMb796a

- 色：明るい青（brand #2f6fdb）、黄色（sun #ffc93c、集まった材料・ほめる印）、緑（ok、「なぜ聞くの？」）、淡い水色の背景。src/app/globals.css の @theme
- 字：丸ゴシック（Zen Maru Gothic、next/font）。見出しは太め
- 形：角の丸いカード、丸いボタン（押すと沈む）、下に厚みのある影
- 動き（src/components/fun.tsx・aio.tsx）：質問カードが右から入る、道のりでえんぴつが1問ずつ進む、答えて進むと上にほめる言葉、材料がポンと黄色に変わる、全部答えると紙吹雪、生成中はえんぴつが書く。記事の画面では上に「質問に答える → 見出しを決める → 本文を整える → コタムに確認 → 公開」の道のりを出し、見出し案・本文ができた直後（1分以内に開いたとき）にほめる言葉と紙吹雪。コピーなどの成功はトーストで知らせる。背景の丸がゆっくり漂う
- 質問ごとに小さな絵（どの材料のための質問かで場面を変える）。人物は案内役の秘書「しおり」（2026-11-01 田村さんが表情15種を用意。public/guide/shiori-*.webp）。使い分け：質問の絵＝質問・指差し・びっくり（数字）・ひらめき（注意点）・応援（次の一歩）、質問の画面の上＝ジャージのストレッチ（1問目）とジャージの応援（2問目から）、材料がそろった＝正解、ほめる言葉と「しおり（コタム）より」＝顔、生成中＝考え中、見出し案＝よくできました、本文ができた・公開後＝ジャージのやりきった笑顔、確認待ち＝おつかれさま（コーヒー）、失敗＝悲しみ、ホーム＝ジャージの応援、ログイン＝おじぎ。喜びは未使用写真にするかは未決定
- コタム側（/coach、企業の詳細、招待、プロフィール）も同じ見た目。管理画面はあいさつとしおり（確認待ちがあれば指差し、無ければコーヒー）、確認待ちは黄色い枠のカードと件数の丸、担当企業のカードに今月の生成回数の棒（2026-11-02）
- AIを待つあいだは、どの画面も同じ待ち画面（src/components/WaitingScreen.tsx）：しおりの表情が切り替わる、回る輪、進む帯、経過秒数、コラム（src/lib/tips.ts。「コタムのこだわり」＝AIのチーム・毎週の海外と国内の情報・成果の出ているお客様の経験・作り話をしない など、と「AIOワンポイント」を交互に。7秒ごとにめくれ、自分でもめくれる）。2026-11-02 田村さん「ゲーム画面のような感じを、全体を通して」
- 答える入力欄には、薄いグレーで記入例（placeholder）を入れて、書く量の目安にする。記事の5つの質問の記入例は、会社の情報に合わせてAIが作り、会社の情報（profile.questionExamples）に残す。最初に質問の画面を開いたときに作り、コタムが会社の情報を書き直したら作り直す。AIの深掘りにはAIが記入例を付ける
- 動きは prefers-reduced-motion で止める。動きがなくても内容が全部読めること
- 幅375pxと1280pxで確認。長い会社名・見出しでも横スクロールやボタン欠けを起こさない

## S1 ホーム

- 上部：会社名、今月の指導方針（顧客向け指導メモの要約）
- 中央：「今月の記事を書く」（主ボタン）、「書きかけの記事を続ける」（最新の作成中記事がある場合のみ）
- 下部：記事一覧。列はテーマ、状態、更新日、コタムのコメント有無
- 数値ダッシュボードを主役にしない

### しおりが育つ（2026-11-02）

- ホーム：しおりの理解度（Lv.1「はじめまして」〜 Lv.7「AIOの名パートナー」、経験値の帯、ポイントのたまり方）と、しおりのメモ帳（会社の知識のカード）。src/components/ShioriGrowth.tsx
- 記事の画面：「しおりが今回使った、あなたの会社の知識」
- 言い回しを覚える：AIが作った版の直後にお客様が直した段落を比べ、「直してもらった言い回し」として会社の知識の先頭に入れる（最近4組まで）
- しおりに教える（/knowledge）：頼み文のコピー → ChatGPT・Claude・Gemini に貼る → 返事を貼る → しおりが読み取った候補から選んで覚える。これまでのブログ記事の取り込み。取り込んだ知識の一覧と「忘れてもらう」。ホームのしおりの理解度から入れる
- しおりの動き：絵は動かさない。しゃべるときは src/components/talk.tsx の ShioriTalk（吹き出し・文字送り）。手順の案内は StepGuide（1つずつ・星とスタンプ・ほめ言葉・紙吹雪）。新しい手順の画面もこれを使う
- 記事の「ブログに載せる」は、1つずつの案内（ブログを開く → タイトル → 本文 → 画像 → 公開 → URL）。コピーだけのボタンは「コピーだけしたいとき」に折りたたむ
- /knowledge は、やり方を3つ（いつものAIにまとめてもらう／会話の記録をまるごと／ブログ記事）から選び、選んだものだけを手順で出す
- /knowledge の「会話の記録をまるごと取り込む（ファイルから）」（src/components/ChatExportImport.tsx）：AIごとの取り出し方、ファイルを選ぶ → 会話の一覧（関係ありそうなものに印・探す欄）→ 選んだ会話をしおりに読んでもらう → 覚えるものを選ぶ
- ホームの「検索での見られ方」（src/components/SearchConsoleCard.tsx）：つながっていなければ「つなぐ」への案内。つながれば28日分の合計4つ、どんな言葉で見つけてもらえたか（上位5）、公開した記事ごと。/search-console は3つの手順（Search Console を開く → コタムのアドレスをコピーして「制限付き」で足す → サイトのURLを入れて「つなぐ」）
- ホームの「しおり通信」（src/components/MonthlyGrowth.tsx）：今月のまとめ4つ、〇か月つづけて書いています、AIに紹介されているか（月4回、結果と出典）
- 前回の続き：質問の1問目の画面に、前の記事で話してくれたお客様の「その後」を聞く任意の欄（PREVIOUS_CASE_QUESTION）

## S2 テーマを選ぶ

- コタムが登録した今月のテーマをカード表示。各カードに「誰の悩みに答えるか」「伝えたい内容」
- 「自分でテーマを決める」カード（タイトルと悩みを入力）
- 会社プロフィールまたは指導メモが未登録なら「コタムが準備中です」と表示し、記事作成へ進ませない（コタムには初期設定へ案内）

### 会社の情報が無いとき（2026-11-02）

- S2 と /profile は「まず、会社のことを教えてください」（会社のことを教える → AIがまとめる → 確かめる）を出す。コタムの登録は待たない
- /profile に「会社のことを教える」の答えを直す・答えからまとめ直す
- テーマがコタムから届いていなければ、「自分でテーマを決める」と「しおりのおすすめから選ぶ」を出す
- ヒアリング（/prototype/hearing）：答えるたびに、しおり（考え中）が「なぜ聞くの？」を添えて深掘りの質問を出す（本物のデータではAIが答えを読んで聞く。1問につき4回まで、「この質問は飛ばす」で終われる）

## S3 質問に答える

- 4〜6問を1問ずつ表示。進捗（例：2／5）、戻る、下書き保存を常時表示
- 各質問に記入例と「まだ分からない」ボタン
- 質問例：
  1. お客様から何を相談されましたか
  2. 実際にはどう対応しましたか
  3. 結果はどうなりましたか（数値があれば）
  4. 注意点や、よくある誤解はありますか
  5. この記事を読んだ人にしてほしいこと（問い合わせ等）
- 回答が具体例に欠ける場合、生成前に追加質問を1〜2問出す
- 全問回答後「見出し案を作る」

## S4 記事を整える

PC：本文を主領域、右に補助領域（タブ：質問回答／指導方針／要確認箇所／コメント）。スマートフォン：上部タブで本文と補助領域を切り替え。

主領域：
- タイトル候補から選択、または直接編集
- 見出しと本文を編集
- 範囲を選んで「短くする」「伝わりやすくする」→ 変更案を差分表示 →「採用」「やめる」
- 「もう一度作る」は新しい版を作る（元の版は残る）
- 版の履歴から以前の版を復元

要確認箇所タブ：
- 数値・実績・価格・顧客名などを一覧表示。該当箇所へジャンプ
- 各項目に「確認した」「修正した」「削除した」。未確認が残っていれば確認依頼・書き出し時に件数を警告（止めはしない）

操作ボタン：
- 「AIOのチェックを実施」（2026-11-02、人の確認の代わり）。押す前に「こんなチェックをします」で11項目（AIOの8つの材料＋数字・実績の確かさ、使ってほしくない言葉、AIっぽさ）を見せる。結果は項目ごとに ✓／！。足りない所があれば、チェック後にポコッと出るウィンドウで一問一答（最大3問）で聞き返す（あとで答えることもでき、記事の画面のいちばん上に「AIから質問が◯つ届いています」を出し続ける。チェック前は同じ場所に「AIOのチェックを実施」）。「記事に反映する」で答えを書き込んだ新しい版を作る。終わったら「チェック済み」。記事を直したら、もう一度チェックできる
- コタムのコメントがあれば、記事の画面の上に「コタムからコメントが届いています」と最新のコメントを出す
- 「タイトルをコピー」「本文をコピー」「HTMLをコピー」。AIOのチェックがまだなら、チェックをすすめる
- 「公開済みにする」（公開URL入力）

コタムが開いた場合：同じ画面で、AIOのチェックの結果とAIとのやり取り（これまでのチェックも）を読み、「コメントを残す」でお客様にコメントを送れる。承認と修正依頼はない（2026-11-02）。

## S5 コタム管理画面

## 画面状態

すべての画面で次の状態を用意する。

| 状態 | 表示 |
|---|---|
| 空 | 次にやることを1文で案内 |
| 読み込み中 | スケルトン表示 |
| 生成中 | 進行表示と「この画面を閉じても続きます」 |
| 生成失敗 | 入力は保持したまま、理由と「もう一度試す」 |
| 利用上限到達 | 「今月の生成回数の上限に達しました。コタムにご相談ください」 |
| 生成を実行中（busy） | 「同じ会社で文章を作っている途中です。終わってからもう一度お試しください」 |
| 予算に達して停止（budget_exceeded） | 「今月は新しい文章を作れなくなっています。コタムにご連絡ください」 |
| 保存失敗 | 未保存であることを明示し、再試行。保存成功前に「保存済み」を表示しない |
| 編集競合 | 「別の画面で更新されました」と、最新版を開くか自分の内容を別版で残すかの選択 |
| セッション切れ | 再ログイン後に同じ画面と入力へ戻る |
| 権限なし | 「この記事を表示する権限がありません」 |
