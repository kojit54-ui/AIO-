# 製造業の知識表

このサービスが製造業に特化している理由の中身。製造業の悩み・発注する人の疑問・Webでうまくいったやり方・買い手の探し方・最近の動き・つまずく言葉のやさしい説明を、公開情報から集めて1つの表にする（src/lib/manufacturing/data.ts）。

## 使い道

| 使う場所 | 何に使うか | 守ること |
|---|---|---|
| 記事の書き手（outline・body・rewrite） | 製造業の会社のとき、書き方のコツ（MFG_WRITER_RULES）と、業種に合う「読む人がよく抱く疑問」6つを `<reader_questions>` で渡す | 疑問は見出しの参考だけ。数字・事例・実績は素材からだけ書く |
| 記事の書き手（同上） | 業種に合う「つまずく言葉」6つを `<reader_terms>` で渡す（readerTermsFor） | 言葉が出てきたら短い説明を添える参考だけ |
| 点検役（review・AIOのチェック） | 実績の具体さ、問い合わせ前の不安への答え、得意と苦手、不具合のときの対応を確かめる | 素材にないことを足させない |
| 書く記事の提案 | `manufacturing_ideas` として記事の案を渡す | 会社の事実としては扱わない |
| ホーム「製造業のこぼれ話」 | 買い手の探し方・うまくいったやり方・言葉の説明から、その日の1つをしおりが話す（3回に2回はその会社の業種の話）。出典リンクつき。/api/manufacturing/tip で1つだけ受け取る | 製造業の会社にだけ出す。データ全体をブラウザに送らない |
| 入口のページ | 「しおりは、ものづくりの現場を勉強しています」で件数・業種の数・疑問の例（サーバーで mfgShowcase を作って渡す） | 売上を約束しない。データ全体をブラウザに送らない |
| 管理画面 /admin/knowledge | 全件を種類・言葉・業種でしぼって見る（100件ずつ） | 全社管理者だけ |

業種は会社の「事業内容」の言葉から当てる（detectIndustries、src/lib/manufacturing/detect.ts。データを読まないので画面から使ってよい）。data.ts は約1MBあるので、"use client" の画面からは index.ts を読まない（管理画面だけは例外）。

## 集め方の決まり

- 公的機関（経産省・中小企業庁・公正取引委員会・自治体・日本政策金融公庫など）、業界メディア（MONOist・日刊工業新聞・ニュースイッチなど）、調査の公開情報を中心にする
- 文章は写さず、要点だけを自分の言葉で（120字まで）。出典の名前・URL・日付を残す
- 中小の会社名や個人が分かる情報は入れない。うまくいった事例は「従業員10人ほどの板金会社」のように書く
- 数字は、出典に書かれているものだけ。誰がいつ調べたかを添える
- 最近の動き（trend）は、正式な発表（official: true）と、報道・見通しを分ける
- 宣伝色の強いマーケティング会社の記事は、やり方の参考にとどめる

## 直すとき

- data.ts を直したら `npm test`（src/lib/manufacturing の形・長さ・URLのテスト）を通す
- 外すときは、その行を消す。足すときは同じ形で、id は種類ごとの続き番号
- 1ターンに検索できる回数に上限（全体で200回）がある。班を分けるときは、1班の回数を決めてから出す
